# Project Setup Workflow
## Discovery
Clarify the goal, users, core features, runtime/framework, storage, authentication needs, deployment target, and testing strategy where these affect architecture.

## Architecture
Propose the smallest viable directory structure, module responsibilities, data flow, configuration, error handling, and testing strategy. Avoid speculative over-engineering.

## Initialize
Create the agreed project skeleton, including appropriate README, environment-variable example, tests, and baseline configuration. Never commit real secrets.

## Verify
Run applicable install, test, lint, type-check, and build commands and report actual results.


## v1.3.2 observability rule
For non-Simple work, emit the Route block immediately after classification and before clarification, planning, blocker messages, or implementation. If TDD is used, include the required TDD Trace with actual execution evidence.
